# Kuruma Race Assistant 要求仕様

## 1. 文書の位置づけ

本書は、軽自動車の耐久レースにおいて、ピットロード制限速度の超過を防ぐための
Kuruma Race Assistantの要求仕様案である。実装着手前の議論用ドラフトであり、
未決事項は「要確認」として明示する。

本装置は運転者の速度管理を補助するものであり、主催者の計測装置や車両の
スピードメータを代替せず、速度超過を完全に防止することを保証しない。
特に20 km/h以下のGNSS速度は、現時点では実車での速度精度と追従性を確認できて
いないため信頼性を保証せず、表示値は参考値として扱う。

## 2. 目的

- ピットロード走行中、運転者が前方から大きく視線を外さずに現在速度と警告状態を認識できる。
- 設定されたピットレーン制限速度に到達した時点を、表示と音で明確に通知する。
- 車速によりピットレーンモードとレースモードを自動的に切り替え、レースモード中は
  ピット速度警告を出さない。
- GNSS測位が無効または信頼できない場合に、速度表示を有効値のように見せない。
- レース現場で短時間に起動・確認・設定でき、走行中の誤操作を起こしにくくする。

## 3. 対象ハードウェア

| 機器 | 用途・前提 |
| --- | --- |
| M5Stack Basic V2.7 | ESP32、320×240 LCD、内蔵スピーカー、物理ボタン3個を使用する |
| M5Stack Module GNSS (M135) | u-blox NEO-M9N-00B、UBX、UART 921600 bps、最大25 Hz更新を使用する |
| M5Stack Battery Bottom 黒 110 mAh V1.1 | 補助電源として使用する |
| microSDカード | 周回基準位置を記載した`courses.txt`の読書きに使用する。走行ログ保存には使用しない |
| 外部GNSSアンテナ | Module GNSS付属のアクティブアンテナを、車外または良好な受信位置に固定する |
| USB電源 | レース中の主電源候補。車両電源から安定化した5 Vを供給する |

### 3.1 ハードウェア上の制約

- Module GNSSのDIPスイッチは、Basicとの組み合わせでUARTを
  `M5Stack TXD G15 → Module GNSS RXD`、`M5Stack RXD G13 ← Module GNSS TXD`
  に設定する。
  Module GNSS基板上の表示ではTXDのG15とRXDのG13だけをONにし、
  PPSおよびほかのTXD/RXD選択肢はOFFにする。
- DIPスイッチは必ず電源を切って変更し、同じTXD/RXDグループ内で
  複数の接続先を同時にONにしない。
- 内蔵110 mAh電池とBattery Bottom 110 mAhだけでレース全時間を賄う前提にはせず、
  USB給電断時のバックアップとして一定時間動作できることを実測する。
- 車両への固定方法、アンテナ配線、電源配線は、振動、脱落、視界妨害、
  操作妨害がないことを実車で確認する。

## 4. 利用シナリオ

1. レース前の準備時に、レース形式を時間制または周回数制から選び、
   終了時刻または規定周回数と周回基準位置を設定して保存し、電源を切る。
2. 周回基準位置は、レーシングコースとピットレーンの両方が合流した共通走路上で
   コースウォーク中に現地登録するか、microSDカードのテキスト設定から選択する。
3. ピット作業者が装置を車両に固定し、外部アンテナと電源を接続する。
4. 電源投入後、装置は前回の進行状態を使わず新しいレースセッションを開始し、
   自己診断、GNSS捕捉および周回計測の開始基準待ちを行う。
5. ピットアウト前に、運転者またはピット作業者が測位有効、警告音、
   設定速度を確認する。
6. 装置は起動時にピットレーンモードとなり、ピットロードでは運転者が
   大きな速度表示と色を確認する。
7. 設定速度40 km/hに到達した時点で、強い表示と警告音で通知する。
8. コースイン後、設定速度以上の状態が設定時間継続するとレースモードへ移行し、
   ピット速度警告を停止する。
9. レースモードでは現在周回と現在スティントの走行時間・周回数を確認する。
   時間制では残り時間、周回数制では残り周回数を確認する。
10. ピットイン時、設定速度以下の状態が設定時間継続するとピットレーンモードへ戻り、
   ピット速度警告を再び有効にする。
11. 車両停止後にCボタンを長押しした場合だけ、前スティントを確定して
   次スティントを開始する。
12. 競技終了後に電源を切ると、そのレースセッションを終了する。次回の
    電源投入では周回数、スティントおよび経過時間を復元しない。
12. GNSS速度が利用不能になった場合は、速度値を無効表示に切り替え、
   専用の異常通知を行う。

## 5. 機能要求

### 5.1 GNSS受信・速度算出

| ID | 要求 |
| --- | --- |
| FR-GPS-001 | UART 8N1でModule GNSSのUBXを受信する。起動時にUBX-MON-VERを921600、38400、460800、230400、115200、57600、19200、9600 bpsで順に照会し、チェックサム正常な応答を検出した速度を自動選択する。通信確立後はUBX-CFG-VALSETでUART1を921600 bps、UBX入出力のみ、Automotive動作モデル、2D/3D自動測位、Static Holdしきい値0.50 m/s、UBX-NAV-PVT出力へ設定する。捕捉中は100 ms/10 Hzとし、有効測位が3秒安定した後に40 ms/25 Hzへ切り替える。設定ごとにACKとUBX-CFG-VALGETの再読出し値を確認し、確認に失敗した場合は再試行する。設定はRAMだけに適用し、BBRまたはFLASHへ保存しない。未検出時は走査を繰り返す。 |
| FR-GPS-002 | UBX-NAV-PVTから測位有効フラグ、Fix種別、対地速度、速度精度、UTC、緯度・経度、衛星数、位置DOPおよび水平位置精度を解析する。 |
| FR-GPS-003 | UBX-NAV-PVTの対地速度mm/sをkm/hに変換する。画面には整数だけを表示するが、警告判定とモード判定には丸め前の速度を使用する。 |
| FR-GPS-004 | UBXチェックサム不正、`gnssFixOK`未成立、Fix種別不正、受信タイムアウト、値域外データを有効速度として扱わない。 |
| FR-GPS-005 | 速度サンプルの時刻と鮮度を管理し、最後の有効値を無期限に表示しない。タイムアウト値の初期案は1.0秒とする。 |
| FR-GPS-006 | 最大25 HzのUBX-NAV-PVT入力をUART受信処理で取りこぼさず解析し、UIへは最新サンプルを上書き通知する。警告判定開始までの装置内遅延はNFR-003を満たす。 |
| FR-GPS-007 | 瞬間的な測位ノイズによる警告の点滅を抑える。ただし平滑化によって警告が遅れないよう、フィルタ方式と最大遅延を実測で決定する。 |
| FR-GPS-008 | 20 km/h以下の速度は、低速域の実車検証が完了するまで精度および追従性を保証しない参考値として扱う。この制約を要求仕様、READMEおよび利用者向け説明に明記する。 |

### 5.2 ピットレーン／レースモード

Tab5版Kuruma-Loggerと同様に、速度しきい値と継続時間を組み合わせた状態機械で
モードを自動切替する。速度しきい値を一度横切っただけでは切り替えず、
設定された継続時間を満たした場合だけ遷移する。

| 現在モード | 遷移条件 | 遷移先 | 初期値 |
| --- | --- | --- | --- |
| ピットレーン | 有効なGNSS速度がレース移行速度以上の状態を、レース移行時間継続 | レース | 60 km/h以上を3秒 |
| レース | 有効なGNSS速度がピット復帰速度以下の状態を、ピット復帰時間継続 | ピットレーン | 40 km/h以下を3秒 |

| ID | 要求 |
| --- | --- |
| FR-MODE-001 | 起動時のモードは常にピットレーンモードとする。 |
| FR-MODE-002 | レース移行速度以上の有効速度がレース移行時間継続した場合、レースモードへ移行する。 |
| FR-MODE-003 | ピット復帰速度以下の有効速度がピット復帰時間継続した場合、ピットレーンモードへ移行する。 |
| FR-MODE-004 | 遷移条件を満たさない有効速度を受信した場合、その方向の継続タイマーをリセットする。 |
| FR-MODE-005 | GNSS速度が無効または古い場合は両方の継続タイマーをリセットし、速度値だけを根拠にモードを切り替えない。 |
| FR-MODE-006 | レースモード中はCAUTION、WARNING、およびそれらの反復警告音・警告点滅を無効にする。 |
| FR-MODE-007 | レースモードからピットレーンモードへ移行した直後から、現在速度に応じたピット速度警告判定を再開する。 |
| FR-MODE-008 | 現在のモードを画面上で常時識別できるようにする。モード遷移時は短時間の表示で通知する。 |
| FR-MODE-009 | ピット速度警告を意図せず無効化しないため、自動モード切替を無効化する設定および固定レースモードを設けない。停止中の手動ピット復帰はFR-MODE-010に従う。 |
| FR-MODE-010 | ピット作業時の確認用として、停止中にピットレーンモードへ手動復帰できる操作を設ける。走行中の偶発操作を防止する。 |
| FR-MODE-011 | 電源再投入時に直前のランタイムモードを復元せず、必ずピットレーンモードから開始する。 |

自動復帰は車速だけを使用するため、低速コーナー、黄旗、セーフティカー、渋滞と
ピット進入を完全には区別できない。ピット復帰速度と継続時間は、対象コースの
最低レース速度およびピット入口から速度計測地点までの所要時間を基に調整する。

### 5.3 警告判定

ピットレーンモード中は、注意開始速度と警告開始速度を直接設定する。
初期値は35 km/hからCAUTION、40 km/hからWARNINGとする。
レースモード中はピット速度警告を出さない。

| 状態 | 判定 | 表示 | 音 |
| --- | --- | --- | --- |
| NORMAL | 注意開始速度未満 | 緑または白 | なし |
| CAUTION | 注意開始速度以上、警告開始速度未満 | 黄 | 短い間欠音 |
| WARNING | 警告開始速度以上 | 赤、必要に応じ点滅 | ピットロード制限速度未満では明確な反復音、制限速度以上では連続したNG音 |
| GPS INVALID | 速度を信頼できない | `---` と「GPSなし」 | 一度測位した後に喪失した時点で、モードを問わず1回だけ専用異常音 |

| ID | 要求 |
| --- | --- |
| FR-ALT-001 | 「ピットロード制限速度」「注意を始める速度」「警告を始める速度」を1 km/h刻みで直接設定できる。 |
| FR-ALT-002 | 設定値は `注意開始速度 <= 警告開始速度 <= ピットロード制限速度` の関係を保つよう補正する。注意開始速度と警告開始速度を同じ値にした場合はCAUTIONを使用せず、その速度から直ちにWARNINGとする。 |
| FR-ALT-003 | CAUTIONとWARNINGに別の表示色・音パターンを割り当てる。 |
| FR-ALT-004 | しきい値付近の状態往復を抑えるヒステリシスを持つ。解除側ヒステリシスの初期案は2 km/hとする。 |
| FR-ALT-005 | WARNINGへの遷移は、平滑化済み速度だけでなく、明らかな単発超過サンプルも考慮する。具体条件は実車データで決定する。 |
| FR-ALT-006 | 内蔵スピーカーを使用し、車内騒音、ヘルメット、エンジン回転中でも認識可能な音量・音程であることを実車試験で確認する。 |
| FR-ALT-007 | 起動後に警告音のセルフテストを行い、ボタン操作で再試験できる。 |
| FR-ALT-008 | ミュートを設ける場合でも走行中に偶発的に無音化しない操作とし、ミュート中は常時画面表示する。 |
| FR-ALT-009 | CAUTIONおよびWARNINGはピットレーンモード中だけ出力する。レースモードへ移行した時点で発音・点滅状態をリセットする。 |
| FR-ALT-010 | 初期設定では注意開始速度を35 km/h、警告開始速度を40 km/hとし、丸め前のGNSS速度が各設定速度以上になった最初の有効サンプルでCAUTIONまたはWARNINGへ遷移する。 |
| FR-ALT-011 | ピットレーンモード中、丸め前の有効なGNSS速度がピットロード制限速度以上の間は、設定された警告音程で連続したNG音を鳴らす。制限速度未満への低下、レースモードへの移行、GNSS速度の無効化、またはピット警告音の無効化で直ちに停止する。 |

### 5.4 画面表示

| ID | 要求 |
| --- | --- |
| FR-UI-001 | ピットレーンモードでは画面の中心に現在速度を小数なしの大型整数で表示し、単位`km/h`を併記する。レースモードはFR-UI-007以降のレース情報を優先する。 |
| FR-UI-002 | ピットレーンモードでは画面全体または広い帯の色でNORMAL、CAUTION、WARNING、GPS INVALIDを区別する。 |
| FR-UI-003 | ピットレーンモードでは設定中の制限速度を確認でき、GNSS状態は両モードで確認できる。 |
| FR-UI-004 | GNSS未捕捉時、速度欄を`---`とし、捕捉待ちであることを表示する。 |
| FR-UI-005 | 直射日光下、夜間、振動中、ヘルメット着用時を想定した視認性を実車で確認する。 |
| FR-UI-006 | 走行中画面は情報を絞り、設定画面への意図しない遷移を防ぐ。 |
| FR-UI-007 | ピットレーンモードでは速度警告を最優先表示する。レースモードでは警告色を常用せず、現在周回、現在スティントの情報を表示し、現在速度は補助情報として小さく表示する。時間制レースでは残り時間、周回数制レースでは残り周回数を主表示とし、両方を同時表示しない。 |
| FR-UI-008 | レースモード中もGNSS異常を視覚表示する。異常音は喪失時に1回だけとし、反復しない。 |
| FR-UI-009 | Kuruma-LoggerのM5Stack CoreS3SE向けGUIを参考に、黒基調のダークテーマ、太い数字、状態色のアクセントという視覚階層を採用する。320×240画面では装飾的なゲージを置かない。ピットレーンモードでは速度を最大要素として中央表示する。レースモードでは、時間制なら残り時間、周回数制なら残り周回数を最大要素、現在周回を次の要素、スティントと速度を補助要素とする。警告またはGNSS異常の情報は発生時だけ表示する。 |
| FR-UI-010 | レースモードでは、レース全体の現在周回、現在スティント番号、当該スティントの経過時間および走行周回数を確認できる。ドライバー名、ドライバー交代予定または次ドライバーは表示しない。 |
| FR-UI-011 | 残り時間およびスティント経過時間は`分:秒`形式で表示する。1時間を超える場合も時間単位へ切り替えず、例として2時間5分7秒を`125:07`と表示する。 |

### 5.5 レース終了条件・周回計測

耐久レースの終了条件を事前に本体へ設定し、レースモード中にドライバーが
残り時間または残り周回数を確認できるようにする。これは走行計画を補助する
参考表示であり、主催者の公式時計、計時結果、チェッカーフラッグを優先する。

| ID | 要求 |
| --- | --- |
| FR-RACE-001 | レース形式を「時間制」または「周回数制」からレース前に選択できる。レース計測中は自動で切り替えず、変更には停止中の確認操作を必要とする。 |
| FR-RACE-002 | 時間制では、レース開催地の終了時刻を時・分で設定し、GNSSのUTCから設定タイムゾーンの現地時刻へ変換して残り時間を算出する。残り時間の画面表示は`分:秒`形式とする。日付をまたぐ大会への対応方法は要検討とする。 |
| FR-RACE-003 | 周回数制では、規定周回数を整数で設定し、GNSS位置から算出した完了周回数と残り周回数を表示する。残り時間は表示しない。 |
| FR-RACE-004 | レース形式、終了時刻、タイムゾーン、規定周回数、選択中の周回基準位置および周回判定パラメータをNVSへ保存し、電源再投入後に復元する。 |
| FR-RACE-005 | 終了時刻または規定周回への到達を画面で明示する。レース中の不要な音を避けるため、終了到達時に通知音を鳴らさない。 |
| FR-RACE-006 | 終了時刻までの残り時間はGNSS時刻を基準とする。GNSS時刻が一時的に無効になった場合は単調時計で継続し、長時間の無効化または時刻の不整合を検出した場合は参考表示であることを示す。 |
| FR-RACE-007 | 周回基準位置はスマートフォン、PC、ネットワークを使用せず、M5Stack本体の画面と3個の物理ボタンだけでも現地登録できる。周回基準位置は、ピットインの有無にかかわらず全周で1回だけ通過する、ピット出口合流点からピット入口分岐点までの共通走路上に置く。ピットレーンが迂回するコントロールライン付近には置かない。 |
| FR-RACE-008 | 周回基準位置登録では、GNSS測位品質が基準を満たし、本体が停止している状態で利用者が「この場所を登録」を実行する。複数秒の位置サンプルを平均し、推定誤差、衛星数およびサンプルのばらつきが基準外なら保存せず再試行を案内する。 |
| FR-RACE-009 | 登録位置を中心とする仮想ゲートへの進入を周回候補とし、ゲートからの退出確認、最小周回時間、進入方向およびGNSS鮮度を組み合わせて同一通過の二重計数と近接区間での誤計数を抑える。進入方向は開始基準となる最初の有効な通過から学習する。ゲート半径等の初期値は実コースで決定する。 |
| FR-RACE-010 | 計測開始前に「周回計測待機」状態を設ける。待機開始時に仮想ゲート内にいる場合は、その滞在と最初の退出を開始基準とする。ゲート外で待機を開始した場合は、最初の有効な進入を開始基準として計数しない。開始基準の確定後は、設定した「開始前に除外する通過回数」を無視し、その次の進入から1周完了として加算する。 |
| FR-RACE-011 | 周回数は公式計時ではなくGNSSによる参考値であることを設定画面と利用者向け説明に明記する。GNSS無効中は周回数を加算せず、復帰時に失われた周回を推測して補わない。 |
| FR-RACE-012 | 登録済み周回基準位置は、緯度経度を通常画面に表示せず、コース名または登録日時と「登録済み」の状態で確認できる。削除および再登録は停止中の確認操作を必須とする。 |
| FR-RACE-013 | レース全体の完了周回数と現在周回を管理する。開始基準確定後から最初の周回中を`LAP 1`とし、仮想ゲート通過ごとに完了周回数を1加算して現在周回を更新する。 |
| FR-RACE-014 | 規定周回数レースでは、`規定周回数 - 完了周回数`を残り周回数として表示する。負数にはせず、規定周回到達後は0と到達状態を表示する。 |
| FR-RACE-015 | 時間制では残り時間を主表示にして残り周回数を表示せず、周回数制では残り周回数を主表示にして残り時間を表示しない。どちらの形式でも現在周回とスティント情報は表示する。 |
| FR-RACE-016 | 電源投入ごとに、保存済み設定から新しいレースセッションを自動作成し、周回計測待機状態へ移行する。設定画面に手動の「新しいレースを開始」は設けない。 |
| FR-RACE-017 | 電源投入による周回計測待機後、FR-RACE-010の開始基準を確定し、設定された除外通過回数を処理する。除外回数が0なら開始基準確定時、1以上なら最後の除外通過時をレース計測開始点として、`LAP 1`とスティント1の計測を開始する。電源投入からレース計測開始点までの待機時間はスティント経過時間へ含めない。 |
| FR-RACE-018 | 完了周回数、現在周回、除外通過状態、現在スティント、スティント履歴および各経過時間はランタイム情報とし、NVSへ保存しない。 |
| FR-RACE-019 | 電源が入っている間は、ピット／レースモード遷移、GNSS喪失または設定画面の終了でレース全体およびスティントのカウンターをリセットしない。電源遮断でそのレースセッションを終了する。 |
| FR-RACE-020 | 電源再投入時は前回のレース進行状態を復元せず、周回数、除外通過状態、スティント、履歴および経過時間を初期化した新しいレースセッションを開始する。 |

#### 5.5.1 microSDによる周回基準位置設定

コースウォーク等で現地登録できない場合に備え、PC等で調べた緯度・経度を
microSDカード上のテキストファイルへ記載し、M5Stack本体から選択できるようにする。
Google Mapsその他の地図サービスとM5Stackが通信する機能は設けない。

| ID | 要求 |
| --- | --- |
| FR-SD-001 | microSDカードの`/gps_speed_meter/courses.txt`をUTF-8のテキスト設定として読み込み、複数の周回基準位置を一覧表示できる。 |
| FR-SD-002 | 各コース設定で周回判定に必須のパラメータは、WGS84の10進表記による`latitude`と`longitude`だけとする。セクション名を本体で選択するためのコース名または地点名として使用する。 |
| FR-SD-003 | テキスト形式はINI形式を基本とし、セクション名ごとに`latitude`と`longitude`を記載する。空行および`#`で始まるコメント行を許可する。 |
| FR-SD-004 | 仮想ゲート半径、退出判定距離、進入方向および最小周回時間はコースファイルの必須項目にしない。半径と退出距離は既定値、進入方向は最初の有効通過からの学習、最小周回時間は共通設定を使用する。 |
| FR-SD-005 | M5Stackの設定画面からmicroSD上のコース名を選択し、緯度・経度を確認して有効化できる。選択したコース名と座標はNVSへ保存し、次回起動時にmicroSDを読めない場合も最後に選択した座標を復元する。 |
| FR-SD-006 | コースウォーク中は、本体操作で約10秒間のGNSS位置を平均し、新しいセクションを`courses.txt`へ追加できる。ディレクトリまたはファイルがなければ作成する。名称入力を要求せず、未使用の`COURSE01`、`COURSE02`等を自動採番する。 |
| FR-SD-007 | microSD未挿入、ファイルなし、読出し失敗、緯度経度の不足、値域外、重複または構文不正を区別して日本語で表示する。不正なセクションは選択できず、ほかの正常なセクションは利用できる。 |
| FR-SD-008 | 本体からファイルを更新する場合は、一時ファイルへ全内容を書き出して検証後に置換し、電源断で既存の正常な設定を失いにくくする。更新前ファイルのバックアップ方法は設計時に確定する。 |
| FR-SD-009 | microSD上の座標設定は周回基準位置の選択にだけ使用し、地図画像、地図URL、APIキーまたは地図サービス固有データを必要としない。 |
| FR-SD-010 | 利用者がPC等で編集できる`courses.txt`のサンプルと、日本語の記入手順をリポジトリおよびREADMEに含める。 |

設定ファイル例:

```ini
# Kuruma Race Assistant course points
[COURSE01]
latitude=36.1234567
longitude=140.1234567

[COURSE02]
latitude=35.9876543
longitude=139.9876543
```

現地登録の第一案は、走行前のコースウォークまたは主催者が許可した時間に、
本体をピット出口合流点からピット入口分岐点までの共通走路へ持参して行う。
設定画面で「周回位置を登録」を選び、GNSS品質が安定してからボタンを
長押しすると、約10秒間の測位サンプルを平均して保存する。競技車両でライン上に
停止することや、走行中のドライバー操作を登録手順の前提にしない。

共通走路へ徒歩で立ち入れない場合は、事前に調べた緯度・経度を
`courses.txt`へ記載してmicroSDカードから選択する。周回数の計数には正確な
コントロールライン位置を必要としないが、
表示する周回更新地点は公式計時とずれるため、ラップタイム用途には使用しない。
車両が安全に停止できない場所での現地登録や、走行中のボタン操作は禁止する。

### 5.6 スティント管理

レース全体の周回数とは別にスティントを管理する。ドライバー交代の有無や
交代予定は管理せず、ピット停止中に利用者がCボタンを長押しした場合だけ
次のスティントへ切り替える。

| ID | 要求 |
| --- | --- |
| FR-STINT-001 | レース計測開始時にスティント1を開始し、現在スティント番号、開始時刻、経過時間および走行周回数を管理する。 |
| FR-STINT-002 | スティント経過時間はスティント開始からの単調経過時間とし、GNSSを一時喪失しても継続する。画面には`分:秒`形式で表示する。スティント走行周回数は、当該スティント中に完了した有効な周回だけを加算する。 |
| FR-STINT-003 | ピットレーンモードかつ有効速度5 km/h以下でCボタンを1秒長押しすると、現在スティントを終了して次のスティントを開始する。ピットレーンモードでGNSS速度が無効な場合は、Cボタンを3秒長押ししたときだけ切り替えを許可する。レースモード中または有効速度5 km/h超では切り替えない。 |
| FR-STINT-004 | スティント切替時は、前スティントの終了時刻、経過時間および走行周回数を確定し、レース全体の時間と周回数はリセットしない。新スティントの経過時間と周回数だけを0から開始する。 |
| FR-STINT-005 | スティント切替成功時は、新しいスティント番号を2秒以上表示し、ピット速度警告と誤認しない短い確認音を1回だけ鳴らす。 |
| FR-STINT-006 | レース画面には現在スティント番号、経過時間および走行周回数を表示する。ドライバー名、交代有無、交代予定または次ドライバーは表示しない。 |
| FR-STINT-007 | ピット／レースモードの自動遷移、周回通過、設定時間経過または規定周回到達ではスティントを自動更新しない。Cボタン長押しが成立した場合だけスティント番号を更新する。Cボタンを長押ししない運用では、レース終了までスティント1を継続する。 |
| FR-STINT-008 | スティント履歴は電源が入っている現在のレースセッション内だけで保持し、電源再投入後には復元しない。 |
| FR-STINT-009 | Cボタン短押しによる警告音テストは維持し、スティント切替の1秒長押しと区別する。長押しが成立した場合は警告音テストを実行しない。 |

## 7. ソフトウェア構成案

要求を満たす最小構成として、以下のFreeRTOSタスクまたはコンポーネントを想定する。

| 構成要素 | 責務 |
| --- | --- |
| GNSS UART Driver | UART受信、リングバッファ、受信タイムアウト検出 |
| UBX Parser | UBXチェックサム検証、NAV-PVT解析、速度・精度・品質スナップショット生成 |
| Racing Mode Domain | 車速と継続時間によるピットレーン／レースモード状態機械 |
| Race Progress Domain | 終了時刻、周回数、周回基準位置の仮想ゲート、計測開始状態の管理 |
| Stint Domain | Cボタン長押しによるスティント切替と、スティント別の経過時間・周回数の集計 |
| Speed Alert Domain | 平滑化、鮮度判定、警告ヒステリシス、ピットモード中の警告状態決定 |
| UI Task | LCD描画、ボタン読取り、設定画面 |
| Alert Output | スピーカーの音パターン再生、セルフテスト |
| Settings Store | NVS読書き、既定値、整合性確認 |
| Course Config Store | microSD上の`courses.txt`読書き、コース一覧、現地登録座標の追加 |
| System Monitor | ウォッチドッグ、起動理由、電源・タスク状態監視 |

タスク間はキューまたは最新値スナップショットで接続し、GNSS受信処理をLCD描画や
音再生でブロックしない。

## 8. Kuruma-Loggerからの再利用候補

Kuruma-Loggerと同じu-blox/UBX系の受信機へ変更したため、次の初期化方式と
設計を本機のNEO-M9NおよびESP32 Basic向けに移植する。

- UBX-MON-VERによるボーレート検出と921600 bpsへの統一
- UBX-CFG-VALSET／VALGETによるRAM設定と読戻し検証
- 捕捉中10 Hz、有効測位安定後25 Hzへの切替
- UBX-NAV-PVTのFix、速度、速度精度、位置、UTCの解析
- ESP-IDFコンポーネント分割とcomposition rootの考え方
- FreeRTOSタスク生成、キュー、ウォッチドッグの運用規約
- M5Unified/M5GFXを使ったLCD、ボタン、スピーカーのハードウェア抽象化
- NVS設定ストア、設定スキーマ、初期値・破損時処理
- GPSスナップショットの鮮度無効化、状態集約、構造化ログ
- `domain/policies/racing_meter.hpp`のピットレーン／レース状態機械と
  `tests/test_domain_racing_meter.cpp`の継続時間・鮮度・ヒステリシステスト
- 純粋な判定ロジックをホスト単体テストする構成

再利用時はKuruma-Loggerのライセンス、依存関係、対象ESP32世代の差を確認し、
必要最小限を移植する。

## 9. 初期スコープ外

- 主催者公式計時システムとの連携
- CANバスからの車速取得
- 公式用途または高精度なラップタイム計測、走行ログのSD保存、クラウド送信
- OTA、Wi-Fi設定ポータル、スマートフォン連携
- ピットロード入口・出口のジオフェンスによる自動警告有効化
- 外部スピーカー、外部LED、専用車載電源基板の製作

将来拡張としては、GNSS位置によるピットロード自動判定、CAN車速との比較、
外部高輝度LED・圧電ブザーを検討できる。

## 11. 確定事項と残課題

### 11.1 確定事項

- ピットレーン制限速度の初期値は40 km/hとし、変更可能にする。
- 注意開始速度と警告開始速度を直接設定し、初期値はそれぞれ35 km/h、40 km/hとする。
- モード切替の初期値は、60 km/h以上を3秒でレースモード、
  40 km/h以下を3秒でピットレーンモードとする。
- 外部5 V給電を主電源としつつ、内蔵電池だけでも一定時間動作可能にする。
- 警告音は内蔵スピーカーを使用する。
- 設定・操作は本体の物理ボタンを主手段とする。
- 速度表示は整数のみとする。
- GNSS異常音は、一度測位した後の喪失時にモードを問わず1回だけ鳴らす。
- GNSSはM5Stack Module GNSS (M135/NEO-M9N-00B)を使用し、
  UARTはM5Stack TX=G15、M5Stack RX=G13とする。
- GNSS通信はUBX、921600 bpsを使用し、有効測位が3秒安定した後は
  UBX-NAV-PVTを40 ms/25 Hzで受信する。
- GNSS精度・遅延はNFR-011およびAT-008の推奨基準で検証する。
- 20 km/h以下の速度は、低速域の実車検証が完了するまで信頼性を保証しない参考値とする。
- レース形式は「時間制」「周回数制」から本体で選択し、時間制では残り時間、周回数制では残り周回数を表示する。
- 周回基準位置はM5Stack本体とGNSSだけで現地登録するか、microSDの事前設定から選択できる構成とする。
- 周回基準位置は、ピットインの有無にかかわらず全周で1回だけ通過する共通走路上へ置く。
- 現地登録できない場合は、microSD上の`courses.txt`へ記載した緯度・経度を本体で選択できる構成とする。
- 残り時間とスティント経過時間は、1時間を超えても`分:秒`形式で表示する。
- ドライバー情報と交代予定は管理・表示せず、ピット停止中のCボタン長押しが成立した場合だけスティントを切り替える。
- 電源投入ごとに新しいレースセッションと周回計測待機を自動開始し、開始基準と除外通過回数の処理完了時から`LAP 1`とスティント1を開始する。
- 電源遮断で現在のレースを終了し、進行状態は保存・復元しない。レース設定と選択中の周回基準位置だけを次回起動へ保持する。
- フォーメーションラップは「開始前に除外する通過回数」0～5回で除外する。
- GNSS速度無効時は、ピットレーンモードでCボタンを3秒長押しした場合だけスティントを更新できる。
- レース終了到達は画面だけで通知し、音を鳴らさない。
- 自動ピット／レースモード切替は無効化できず、固定レースモードを設けない。

### 11.2 残課題

- 黄旗、セーフティカー、低速コーナーでピットレーンモードへ誤復帰しない条件はTBD。
- 「開始前に除外する通過回数」によるスタンディング／ローリングスタートの計数結果は実コースで確認する。
- 仮想ゲート半径25 m、退出距離40 m、進入方向許容角90度、
  最小周回時間30秒を初期実装値とし、実コースで妥当性を確認する。
- 現地登録は衛星6個以上、位置DOP 2.5以下、5 km/h以下、位置のRMSばらつき10 m以内で
  10秒間に20サンプル以上を初期合格値とし、実コースで妥当性を確認する。
- 周回判定に使用する測位品質は衛星4個以上、位置DOP 4.0以下を初期値とする。
- `courses.txt`は最大8 KiB、24地点、セクション名24バイトとする。
  本体更新時は更新前ファイルを`courses.bak`へ保持する。
- レース終了時刻の日付またぎと、スタート遅延時の時刻修正手順はTBD。
- 取付位置、視認距離、昼夜の画面輝度、グローブ着用時の操作性は実車で決定する。
- 内蔵電池での実際の連続稼働時間と、最低30分・目標60分の達成可否を実測する。
