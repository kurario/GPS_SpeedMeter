# Kuruma Race Assistant

M5Stackを使った耐久レース向けGPSアシスタントです。最大25 Hzの車速表示、
ピットレーン速度警告、周回計測、残り時間・周回数、スティント管理を搭載しています。

M5Stack Basic V2.7とModule GNSS (M135)で動作し、ESP-IDF v5.5.1と
FreeRTOSで実装しています。起動時は黒基調の専用画面に
「KURUMA RACE ASSISTANT」と「by kurumario」を表示し、
2秒後に速度画面へ移行します。GNSSの測位完了を待たずに画面操作できます。

正本となる要求は [docs/requirements.md](docs/requirements.md) を参照してください。

本プロジェクトはM5Stack Technology Co., Ltd.の公式プロジェクトではありません。
M5Stackおよび関連する製品名は、対応ハードウェアを説明する目的で使用しています。

## 主な機能

- u-blox UBX-NAV-PVTのGPS車速を最大25 Hzで取得し、大きな整数表示で提示
- ピットレーンモードとレースモードを車速・継続時間から自動切替
- 時間制／周回数制レースの残り情報、現在周回、スティント情報を表示
- microSDの緯度・経度または10秒間の現地平均から周回ポイントを登録
- 電源投入ごとに新しいレースを自動開始し、前回の周回・スティントは復元しない
- 注意速度では黄色、警告速度では赤色の表示
- ピット制限速度以上では、制限速度未満へ戻るまで連続したNG音
- 本体の3ボタンだけで速度、切替時間、音量、明るさなどを設定
- 設定値をNVSへ保存し、再起動後も保持
- Module GNSSのUBXボーレートを自動検出
- 起動ごとにUBX設定を送信し、車載モデル・Static Hold・更新周期を読戻し確認

20 km/h以下の速度は、現時点では実車での精度と追従性を確認できていないため、
信頼性を保証しない参考値です。

開発と書き込みには、データ通信対応のUSB Type-Cケーブルと、macOSまたは

コネクターが抜けないよう固定してください。

### Module GNSSのDIPスイッチ設定

Module GNSSのDIPスイッチは、Basic向けに次のUARTピンを選択します。

- M5Stack TXD G15 → Module GNSS RXD
- M5Stack RXD G13 ← Module GNSS TXD
- PPSはすべてOFF

Module GNSS基板上の表示では、TXDグループのG15とRXDグループのG13だけを
ONにし、ほかのTXD/RXDおよびPPSをOFFにします。同じグループ内で複数の
接続先を同時にONにしないでください。基板上のTXD/RXDはM5Stack側の信号名です。
ファームウェアではUART TX=G15、UART RX=G13を使用します。

組み立て前にM5StackとModule GNSSの電源を切り、DIPスイッチを設定してから
モジュールを積み重ねてください。GNSSアンテナは空が見える位置へ設置します。

## GPSモジュールとの通信

起動時に921600、38400、460800、230400、115200、57600、19200、9600 bpsで
UBX-MON-VERを順に送信し、チェックサムが正常な応答を返したボーレートを
自動選択します。Module GNSSの工場出荷時ボーレートは38400 bpsです。

通信確立後はUBX-CFG-VALSETでUARTを921600 bps、UBX入出力のみ、
Automotive動作モデル、2D/3D自動測位、Static Hold 0.50 m/s、
UBX-NAV-PVT出力に設定します。捕捉中は10 Hzで動作し、有効測位が3秒間
安定した後に25 Hzへ切り替えます。設定値はUBX-CFG-VALGETで読み戻して
一致を確認します。設定は揮発RAMだけに適用し、BBRやFLASHへ保存しないため、
起動ごとに同じ初期化を行います。

速度はUBX-NAV-PVTの対地速度を使用し、同時に`gnssFixOK`、Fix種別、
速度精度、衛星数、位置DOP、水平位置精度を診断情報として取得します。

## 開発環境のセットアップ

ビルドには [ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/get-started/) v5.5.1が必要です。
[公式手順](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/get-started/index.html#installation)に従ってインストールしてください。

必要なホスト側ツール:

- Git
- ESP-IDF v5.5.1がサポートするPython環境
- CMakeとC++コンパイラー（ホスト単体テストを実行する場合）
- USBシリアルドライバー（PCがM5Stackを認識しない場合）

```sh
git clone -b v5.5.1 --recursive https://github.com/espressif/esp-idf.git
cd esp-idf
./install.sh esp32
```

依存コンポーネント(M5Unified)は、初回ビルド時にESP-IDF Component Managerが
[main/idf_component.yml](main/idf_component.yml) と
[dependencies.lock](dependencies.lock) に基づいて自動取得します。

## ビルドと書き込み

```sh
# ソースコードの取得
git clone https://github.com/kurario/Kuruma-Race-Assistant.git
cd Kuruma-Race-Assistant

# ESP-IDF環境の読み込み（インストール先に合わせてパスを変更）
. <ESP-IDFのインストール先>/export.sh

# 初回だけターゲットを指定
idf.py set-target esp32

# ビルド
idf.py build

# 書き込みとシリアルログ表示
idf.py -p <シリアルポート> flash monitor
```

シリアルポートは、macOSでは`/dev/cu.usbserial-XXXX`、Linuxでは
`/dev/ttyUSB0`などです。`idf.py -p`を省略すると自動検出を試みます。
シリアルモニターは`Ctrl+]`で終了できます。

書き込み後は、起動画面が2秒間表示されてから速度画面へ移行します。
初回測位には屋外で数分かかる場合があります。測位前の速度表示が無効でも、
UBX受信とNEO-M9N設定が正常なら故障ではありません。

## ホスト単体テスト

UBX/NAV-PVTパーサーなどのロジックは、ESP-IDF環境なしでホスト上でテストできます。

```sh
cmake -S tests -B build_host
cmake --build build_host
ctest --test-dir build_host --output-on-failure
```

## 操作

通常画面:

- A長押し: 5 km/h以下でピットレーンモードへ手動復帰
- B長押し: 停止中に設定画面を開く
- Cクリック: 警告音テスト
- C 1秒長押し: ピットモードかつ有効速度5 km/h以下で次のスティントへ切替
- C 3秒長押し: GPS速度が無効な場合に次のスティントへ切替

設定画面:

- A: 値を下げる
- B: 次の項目
- C: 値を上げる
- B長押し: NVSへ保存して終了

レース設定では、レース形式、終了時刻、開催地の時差、規定周回数、
開始前に除外する通過回数、周回ポイントを設定できます。
設定値と選択した周回ポイントはNVSへ保存され、次回以降も使用します。
電源投入ごとに前回の周回・スティントを破棄して、新しいレースの
周回計測待機へ自動的に移ります。電源を切るとそのレースは終了し、
再投入しても進行状態を復元しません。走行中は設定画面を開けません。

「電源投入でレース開始」はレースセッションの開始を意味します。実際の
`LAP 1`とスティント1の計時は、登録した周回ポイントで開始基準と
設定済みの除外通過回数を処理した時点から始まります。

初期設定は、ピット制限40 km/h、60 km/h以上を3秒でレースモード、
40 km/h以下を3秒でピットレーンモードです。
速度警告は35 km/hから黄色の注意、40 km/hから赤色の警告を開始します。
注意開始速度と警告開始速度は、設定画面で1 km/h刻みに直接変更できます。
ピットレーンモードで丸め前の速度がピット制限速度以上になると、
制限速度未満へ戻るまで連続したNG音を鳴らします。レースモード、GPS無効、
またはピット警告音オフではNG音を停止します。

### microSDのコース設定

microSDカードに`/kuruma_race_assistant/courses.txt`を作成します。文字コードはUTF-8、
ファイル形式は次のINI形式です。サンプルは
[examples/courses.txt](examples/courses.txt) にあります。

```ini
[COURSE01]
latitude=36.1234567
longitude=140.1234567

[COURSE02]
latitude=35.9876543
longitude=139.9876543
```

`latitude`は緯度、`longitude`は経度をWGS84の10進表記で指定します。
セクション名は本体のコース名になり、最大24バイト・最大24地点です。
同じ名称または同じ座標の重複、不足項目、値域外の座標は選択できません。
Google Mapsと本体が通信する機能はなく、調べた座標を手作業で入力します。

周回ポイントは、ピットインの有無にかかわらず全周で一度通過する、
ピット出口合流点からピット入口分岐点までの共通走路上を選んでください。
ピットレーンが迂回するコントロールライン上へ置くと、ピット通過周を
数えられないため不適切です。

現地登録する場合は、安全に徒歩で立ち止まれる場所でGPSを安定させ、
設定画面の「この場所を登録」でCを押します。衛星6個以上、位置DOP 2.5以下、
速度5 km/h以下で位置ばらつき10 m以内のサンプルを10秒間平均し、
`COURSE01`から自動採番して保存します。
更新前ファイルは`courses.bak`へ残します。競技車両の走行中や、
立入禁止場所では登録操作をしないでください。

### 初回起動時の確認

1. 屋外で電源を入れ、起動画面と起動音を確認します。
2. GPS測位後、停止中に速度が0 km/h付近になることを確認します。
3. Cボタンで警告音をテストします。
4. Bボタン長押しで設定画面を開き、ピット制限速度を確認します。
5. 実車走行前に、安全な場所で表示速度とモード切替を確認します。

## 画面表示

走行画面は黒基調のダークテーマです。ピットモードは速度を画面高の大半を使って最大表示し、
通常時は小さな走行モード、ピット制限速度、単位だけを併記します。
ピット警告時は赤または黄、レースモードは青、GNSS無効時は灰色の外枠で表示します。
レースモードでは、時間制なら残り時間、周回数制なら残り周回数を最大表示し、
現在周回、現在スティントの経過時間・周回数、補助的な速度を表示します。
周回数は公式計時ではなくGNSSによる参考値です。

設定画面は、レース参加者がマイコンの知識なしに操作できるよう、全項目に
日本語の名称と説明を表示します。音量と明るさは百分率、切替項目はオン/オフで
表示し、Aで減らす、Bで次へ、Cで増やす、B長押しで保存して戻ります。

## トラブルシュート

### 速度が表示されない

- GNSSアンテナを接続し、屋外の空が広く見える場所で数分待ってください。
- Module GNSSのM5Stack側TXD G15、RXD G13用DIPスイッチと、ほかのスイッチが
  OFFか確認してください。
- シリアルログで`NEO-M9N detected`、各`UBX config`の`verify=ok`、
  測位後に`NAV-PVT promoted to 25 Hz`が出ているか確認してください。

### 書き込みできない

- データ通信対応USBケーブルへ交換してください。
- シリアルモニターなど、ポートを使用中のアプリを終了してください。
- M5Stackを書き込みモードで起動してから、もう一度`idf.py flash`を実行してください。
- Linuxではユーザーがシリアルポートを使用できる権限を持つか確認してください。

### 速度の反応が遅い

UBX設定の読戻し検証が成功していることと、測位安定後のログが40 ms/25 Hzに
なっていることを確認してください。GNSSの受信環境が悪い場合は、更新周期が正常でも
測位結果が遅れたり無効になったりします。

## 安全上の注意

本機はドライバー支援用の試作機であり、競技規則への適合や速度計としての精度を
保証するものではありません。GPS速度には受信環境による遅延や誤差があります。
特に20 km/h以下の表示値は低速域の実車検証が完了しておらず、信頼性を
保証していません。
車両の純正速度計、ピットクルーの指示、主催者の規則を優先し、走行前に十分な
動作確認を行ってください。運転中に設定操作をしないでください。
